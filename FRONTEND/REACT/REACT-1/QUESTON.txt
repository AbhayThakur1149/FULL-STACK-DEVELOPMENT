28) How VITE Works?
      a) Development (using browser native ESM (ECMA Script Modules))
            I) Browser led loading 
                Modern web browser supports ESM so they can directly map through the modules
            II) On demand compiling 
                 When we start VITE the server launches instantly because it does not browser rEADS YOUR CODE AND explicitly requests on the files needed for that very specific page 
                 VITE intercepts these requests and transform the files on the fly and serves them to the browser 
                 No wasted processing if your application has 1000 pages but you are looking only on the home page the VITE processes the only home page
            III) Dependency pre-bundling 
                 In developing the application the source code of the application changes frequently but the dependency remains constant therefore VITE bundles them seperatly 
            IV) Smart hot module replacement (SHMR)
                    In the traditional setup saving a file forces the bundler to reevaluate the bundle graph and rebuild it piece by piece 
                    In VITE files are served using native ESM so therefore there is the direct link between the browser and the file 
                    Thats why in the case of changes only the module that is changed is updated 
      b) Production
            I) Bundling with rollup 
            II) Optimization 
            III) Rollup outputs 
            IV) Async chunk loading
